# AIC Adopters

AIC records adopters only after their maintainers submit a public, reproducible conformance claim that can be verified with the open tooling in this repository.

## Verified external adopters

None yet.

This is an honest launch metric, not an empty showcase. A repository link, logo, local demo, or self-description is not enough to qualify. See [Submit an adopter claim](./docs/adopter-submission.md) for the evidence and review requirements.

## What qualifies

An external adopter must:

1. be operated outside the AIC repository and organization;
2. publish an authored behavior contract for a real application operation;
3. run an applicable AIC conformance pack or an equally strict reviewed contract;
4. publish a passed proof and a deployment-bound signed claim;
5. provide a public key and origin-scoped trust information;
6. make the artifacts independently reproducible or verifiable; and
7. consent to being listed.

Registry inclusion means the submitted artifacts verified at review time. It is not certification, a security warranty, an endorsement, or a promise that the deployment remains reachable.
